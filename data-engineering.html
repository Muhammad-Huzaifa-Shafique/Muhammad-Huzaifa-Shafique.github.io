Data engineering / Oklahoma legislature vote extractor

Oklahoma legislature vote extractor, and the checks I ran on its output

A Python tool that collects House and Senate vote records from the Oklahoma legislature's public pages and writes three CSV files: one row per vote, one row per member's vote, and a list of members. It was a team project with classmates in a graduate course (GRT713), and my part was the House votes. This page shows what the House output contains and where it falls short.

Relevant to: web scraping (asyncio, aiohttp), parsing semi-structured text with regular expressions, data cleaning, data validation and data-quality checks, reconciling two tables, pandas, tidy CSV output.

What it does

Most machine-learning projects start with records nobody prepared for analysis. This is that first step on a messy public source: collect many pages in parallel, cut each vote out of the page text, clean names and duplicates, and save tables that pandas or a database can load.

  1. Find the votes. In Auto mode it tries vote ID numbers on the former House site for the 47th to 60th Legislatures, or walks the Senate site's pages for 2006 to 2025. In manual mode you pick your own files or links.
  2. Fetch and read. Pages are fetched in parallel with asyncio and aiohttp, and PDFs are converted to text. Each vote is cut out of the page text.
  3. Clean. For each vote it reads the bill number, type, the counts (Yea, Nay, CP, Excused, Vacant), the result, place, date and time, and the member names under each count. It splits names that were run together, removes titles and drops duplicate records.
  4. Save. It writes the three CSV files below.

Checking the output

The extractor had no tests, so I ran a short pandas script (audit_output.py) over the House output. Each vote page gives counts (for example, 87 Yea and 10 Nay) and then lists the member names under each count, so the two can be compared. Here is what the checks found.

Why is that? I have not traced the cause. Either the extractor drops names while cutting votes out of the page text, or the pages themselves list fewer names than their counts. Reading a few source pages against their rows is the next step, and the check script now makes the effect measurable.

Limits and next steps

  • Written for the sites as they were in fall 2025. Page layouts and addresses may have changed since, so check a few pages before relying on it.
  • The checks cover the House output only. The script can also collect Senate votes, but I have not run those files through the same checks.
  • Parsing relies on text patterns. An unusual layout can drop a vote or split a name in the wrong place, which fits what the checks found.
  • It is one long script that asks its questions through dialogs rather than command-line options.
  • No data is included in the repository. The CSV files are created when you run it.

Next: hand-count a few saved pages and use them as tests, find where the missing names go, then split the script into modules with command-line options.

Fixed-width data extractor

A second data-preparation script, written for the same course together with a classmate. It turns a fixed-width text report into a clean Excel table: it finds the columns from the report's header, rebuilds rows that wrap across several lines, and saves a formatted .xlsx file next to the input. We compared our outputs on the course file and they matched.

  1. Find the columns. The header line with the most gaps of four or more spaces is the template, and each gap marks a column boundary.
  2. Build the column names. The three header lines are merged piece by piece, so a name that wraps over three lines becomes one name.
  3. Find the rows. A new record starts when column 19 is not blank. A line where it is blank continues the previous record.
  4. Rejoin wrapped text. If the previous piece filled its whole column, the next piece is joined with no space (a word cut in the middle). Otherwise it is joined with one space.
  5. Write the Excel file. Bold header row, wrapped text, fitted column widths, a frozen header and an auto-filter.
